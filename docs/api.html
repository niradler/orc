REST API ​

The ORC HTTP API: base URL, auth, the OpenAPI spec, the TypeScript SDK and the route groups.

Base URL ​

ItemValue
Base URLhttp://127.0.0.1:7700 (api.host / api.port, or ORC_API_HOST / ORC_API_PORT)
Route prefix/api
OpenAPI 3.1 specGET /openapi.json
Swagger UIGET /docs
Health (no auth)GET /api/health
MCP endpoint/mcp (see MCP)

Errors return { "error": "<message>", "code": "<CODE>" } with a matching status, for example VALIDATION_ERROR (400).

Auth ​

When api.secret (or ORC_API_SECRET) is set, every /api/* route, /openapi.json and /docs require one of:

CredentialHow
API secretAuthorization: Bearer <secret>
Access tokenAuthorization: Bearer <token> from POST /api/auth/token
Browser sessionCookie set by POST /api/auth/session (web dashboard)

With no secret, the API is open. ORC logs a security warning when it binds a non-loopback host without a secret.

Create an access token:

bash
curl -s -X POST http://127.0.0.1:7700/api/auth/token \
  -H "Content-Type: application/json" \
  -d '{"secret":"'"$ORC_API_SECRET"'","expires_at":1767225600}'

expires_at is Unix seconds; it defaults to api.session_days from now and is capped at 365 days.

Unauthenticated exceptions: GET /api/health, the sign-in routes, POST /webhooks/{token} (signed deliveries), and signed short-lived capability URLs (skill downloads, scratchpad content, session uploads).

Usage ​

Desktop preview ​

The desktop panel uses authenticated /api/desktop-preview/* routes: GET session?session_id=… resolves a trusted session; GET file?session_id=…&target=… reads bounded workspace text/images; PUT file saves text using {session_id,target,content,original} and returns 409 if disk content changed. Paths are constrained to that session's working folder and execution host.

POST clients registers {client_id,session_id,agent_access,browser_ready} and returns a private lease. Renewal, GET clients/{id}/requests, POST clients/{id}/close and POST requests/{id}/ack require X-Preview-Lease as well as normal API auth. GET clients?session_id=… lists targets (agent_access, browser_ready) without exposing leases. POST requests queues {session_id,client_id?,kind:"url"|"file",target}; POST browser queues {session_id,client_id?,command,tab_id?} only for an opted-in target with an open browser page (browser_ready), otherwise it returns 409. GET requests/{id} reports queued, opened, completed, failed or expired. POST requests/{id}/cancel fails a still-queued request so it never runs late; the MCP server calls it when a browser action is still queued after its 10-second wait. Queued work expires; it is not persisted across daemon restarts.

Browser files stay inside the session workspace: POST artifact?session_id=…&name=… saves a browser download (octet-stream body), POST recording?session_id=… saves a WebM recording, and GET upload?session_id=…&target=… returns a workspace file as base64 for a browser upload. Artifact and recording bodies are capped at 16 MB. See MCP preview tools for browser commands and permission behavior.

GET /api/sessions/live/{id}/cache returns numeric prompt-cache evidence from a stored native session transcript: latest (including optional recorded time and a conservative may_be_cold_after hint) and totals. Missing or unsupported evidence is null. No prompt text, credentials or transcript paths are returned. The route uses normal API authentication and the session's stored execution host; clients cannot supply a file path. The SDK exposes orc.sessions.cacheUsage(id).

GET /api/usage/history?days=30 returns imported session lifetime token totals, grouped by agent and UTC session start date. days accepts 7, 30 (default), 90, or 0 for all time. Totals include session count, recorded tokens, unknown counts and estimated counts; these are session cohorts, not daily billed usage.

GET /api/usage/quotas returns local Codex and Claude quota windows with percentage used, reset timestamps, availability and check time. Requests share a 60-second cache. Neither route returns credentials. Both use normal API authentication. See Usage in Settings for account support and history limits. The SDK exposes orc.usage.history("30") and orc.usage.quotas().

Pagination ​

GET /api/projects, GET /api/jobs and GET /api/skills take limit and offset and return next_offset; follow it until it is null. Projects and jobs default to 50 per page (max 100); skills default to 30 (max 500).

Examples ​

bash
H="Authorization: Bearer $ORC_API_SECRET"

curl -s -H "$H" http://127.0.0.1:7700/api/projects/by-name/my-app
curl -s -H "$H" "http://127.0.0.1:7700/api/tasks?status=doing&limit=20"
curl -s -H "$H" -X POST "http://127.0.0.1:7700/api/jobs/<job-id>/trigger?sync=true"
curl -s -H "$H" -H "Content-Type: application/json" -X POST http://127.0.0.1:7700/api/kb/search \
  -d '{"query":"rollback procedure"}'

TypeScript SDK ​

@orc/sdk (packages/sdk) wraps the API. It reads ORC_API_BASE (or the configured host and port) and api.secret unless you pass them.

ts
import { createOrcClient } from "@orc/sdk";

const orc = createOrcClient({ baseUrl: "http://127.0.0.1:7700", secret: process.env.ORC_API_SECRET });
const { data, error } = await orc.tasks.list({ status: "doing" });
OptionPurpose
baseUrlAPI origin, without /api
secretBearer secret or access token
project_idActive project for knowledge scope
actor{ name, session_id } attribution for knowledge reads and writes
sourceCall source for knowledge edit rights (api by default)

Every method returns { data, error }; error is { error, code } and never throws. Types generated from the OpenAPI spec live in packages/sdk/src/openapi.gen.ts (regenerate with bun run generate in packages/sdk).

Projects accept an optional workspace object with setup_script, dev_script, setup_timeout_secs, port_base, port_count and env. env is the same { name, value, secret } array as job environments: secret values are encrypted at rest, read back as value: null, and retained when that saved null placeholder is sent again. Omitting workspace on update preserves it; sending one without a stored secret's value returns 400. An invalid or missing stored value falls back to defaults: no scripts, a 900-second setup timeout, ten ports starting from 3100, and no variables.

GET /workspaces returns workspace records with setup_status, setup_output, the allocated port_base/port_count block, preview_url and the owning project. Filter by project_id, or pass path for exactly one folder. Setup runs once per managed worktree; a project's main checkout gets a port block but no setup.

Jobs accept optional settings and environment in create/update requests. settings is replaced as a whole when supplied: host is an SSH alias, null pins the local host, and omission follows the selected execution host; timezone is an IANA timezone for cron. shell is { executable, args }, with the script appended as the final argument. workspace is { mode: "directory" | "worktree", base_ref, cleanup_on_success } for agent jobs. Legacy jobs without settings retain their previous shell and directory behavior. inherit_project_directory: false preserves a command job’s host working directory when adding settings to a legacy job; new jobs otherwise inherit their project path. The Jobs response includes working_dir, settings, schedule_timezone and a timezone-aware next_run_at for enabled cron jobs.

environment is an array of { name, value, secret }. Secret values are encrypted at rest and read back as value: null; submitting that saved name with secret: true and value: null retains its value. Omitting the array preserves all entries; supplying an array replaces it, and an empty array clears it. Names are unique (case-insensitive), ORC_ names are reserved, and values are single-line. Exact secret values are redacted from job logs and saved agent summaries. Legacy env_vars inputs remain supported as nonsecret values; reads expose them through environment. Do not supply both forms in one write. Agent action.options accepts the shared validated launch-options contract for its backend; automatic approval requires action.auto_approve: true.

Job runs expose session_id for the audit record and native_session_id for the provider identity. The run-session resolver checks run ownership and discovers only that native conversation on its recorded execution host. It does not switch the global execution host. Existing authentication protects both endpoints.

GET /chat/models also accepts optional host and cwd for a job destination. Omit host to follow the selected host, use __local__ to pin local, or supply an SSH alias. An existing threadId owns its host/directory and rejects these overrides.

Chat streams include turn events with startedAt (Unix milliseconds), followed at completion by finishedAt, durationMs and outcome (completed, stopped, or failed). The same optional turn object is persisted on assistant messages. durationMs prefers the backend's reported duration and otherwise uses server elapsed time. Replay includes the original start; legacy messages may omit turn. Before a tool call, a narration event moves accumulated prose out of the current reply and into its folded activity. Its text preserves that prose for expansion.

A turn opens with a thread event carrying the conversation metadata and only that turn's user message; the full transcript is read from GET /chat/threads/{id}. POST /chat/stream accepts an optional clientMessageId (UUID) and stores it as the user message id, rejecting a repeat with 409. If a first send's response is lost, poll GET /chat/threads/by-message/{clientMessageId} — 404 until the server stores the message, then the full thread — and attach to /chat/threads/{id}/live instead of sending the message again.

First sends reserve clientMessageId before agent and workspace preparation. Repeating that ID without a thread returns 409 with code CHAT_MESSAGE_EXISTS, including while preparation is pending. Recover the original thread by message ID; retrying the same queued message does not start another turn. The web client bounds recovery requests and backoff to 15 seconds, or 60 seconds after a server error, header timeout or CHAT_MESSAGE_EXISTS, then pauses the message in its queue.

POST /terminals accepts project_id to use that project's workspace environment and ports, and dev: true to run its dev script in a shell terminal. A dev terminal rejects an agent kind or providerId, and fails when the project has no dev script. Terminal responses include project_id, worktree_path, dev and preview_url. For a dev terminal, the first printed http(s) URL becomes preview_url and stays until that terminal exits.

Notifications and audit ​

All paths below use the /api prefix and the normal API authentication.

MethodPathPurpose
GET/notificationsCurrent history, shared unread count and has_more
PATCH/notifications/{id}Shared {read?: boolean, dismissed?: boolean}
POST/notifications/readMark all current notifications read

Listing accepts limit (1–100, default50), offset (default0) and unread=true|false (defaultfalse). Each notification includes a generic type, source_id, title, body, level (needs-you or done), nullable project_id, internal path, requires_action, and millisecond timestamps created_at, expires_at, read_at, dismissed_at (the last two nullable). Expiry and dismissal do not mutate the source request. SDK methods are client.notifications.list, .update and .markAllRead.

GET /audit accepts entity_type (notification, human_request, job_run, task, settings, job, rule, terminal, auth, memory, skill, kb), session_id, since (Unix seconds), limit (1–100, default50), and project_id or scope=global|all. scope=all includes project and global entries. snapshot=preview substitutes a bounded marker for snapshots larger than4096 bytes; default full preserves the original snapshot. The Audit UI uses previews and displays the latest100 matching events. Audit timestamps use Unix seconds. Both notification and audit reads enforce their configured retention periods; see Notifications.

Agent capabilities and steering ​

GET /backends includes a versioned capabilities object for each integration. GET /chat/capabilities?agent=<id>&threadId=<optional-thread-uuid> returns { backend, capabilities } without starting a provider. Capability flags describe resume, model selection, image input, tool output, approvals, questions, live permissions, native interruption, steering, MCP, fork and rollback. source is adapter, negotiated or unknown; unsupported and unknown operations are false. Chat SSE emits capabilities events and persists negotiated values with the thread.

POST /chat/runs/{id}/steer takes { "requestId": "<uuid>", "input": "Focus on the failing test" } and returns the updated conversation after the active native turn accepts it. It requires a live steering-capable session; stale and unsupported runs return 409. It keeps the original native thread and turn. Empty input is invalid. These routes use the same authentication as the rest of the API. The SDK exposes client.chat.capabilities(agent, threadId?) and client.chat.steer(runId, input, requestId?). Reuse the same request ID and input when retrying. A duplicate ID with different content returns 409; a live run accepts at most 32 distinct steering requests. The intent is saved before native delivery. An initial save failure sends nothing. Unconfirmed delivery is retained in history and cannot be resent with the same ID; a delivery-status save failure reports a warning while keeping the saved intent.
