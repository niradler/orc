Install ​

How to install ORC as a desktop app, a standalone binary, an npm package, a Docker container or from source, and how to upgrade each.

MethodBest forNeeds
Desktop appYour own machineNothing
Pre-built binaryServers, CI, headless machinesNothing
npmMachines that already have BunBun >= 1.4.4
DockerContainers, shared hostsDocker
From sourceContributorsBun >= 1.4.4, git

Desktop app ​

The recommended install. Download the installer for your machine from GitHub Releases.

OSInstaller
macOS (Apple Silicon)orc-<version>-mac-arm64.dmg
Windows (x64)orc-<version>-win-x64.exe
Linux (x64)orc-<version>-linux-x86_64.AppImage
Linux (ARM64)orc-<version>-linux-arm64.AppImage

There is no Intel macOS installer. On an Intel Mac, use the orc-mac-x64 binary.

On Linux, make the AppImage executable before running it:

bash
chmod +x orc-*-linux-*.AppImage
./orc-*-linux-*.AppImage

Unsigned builds

On macOS, right-click the app and choose Open the first time. On Windows, choose More info, then Run anyway.

What the app sets up ​

On launch the app:

StepDetail
Starts the daemonReuses a daemon already healthy on the configured port (api.port, default 7700), otherwise starts the bundled orc binary. Only a daemon the app started is stopped when the app quits.
Sets an API secretWhen no secret is configured and the app starts the daemon, it generates one, saves it as api.secret in ~/.orc/config.json and sends it on every dashboard request.
Installs the CLICopies orc to ~/.orc/bin (orc.exe on Windows). Re-copied when the app version changes.
Adds the CLI to PATHzsh: ~/.zshenv. bash: ~/.bash_profile (and ~/.bashrc if present) on macOS, ~/.bashrc (and ~/.profile if present) on Linux. fish: ~/.config/fish/conf.d/orc.fish. Windows: the user PATH. Open a new terminal afterwards.
Starts at loginEnabled on first run, started hidden. Toggle it from the tray menu.
Adds a tray iconOpen orc, Start at login, Quit orc.

Daemon output goes to ~/.orc/desktop-daemon.log.

Verify the CLI from a new terminal:

bash
orc status

See Desktop app and web dashboard for the app tour.

Pre-built binary ​

Single-file binaries with the web dashboard embedded. No runtime needed.

bash
# macOS (Apple Silicon)
curl -L https://github.com/niradler/orc/releases/latest/download/orc-mac-arm64 -o /usr/local/bin/orc && chmod +x /usr/local/bin/orc

# macOS (Intel)
curl -L https://github.com/niradler/orc/releases/latest/download/orc-mac-x64 -o /usr/local/bin/orc && chmod +x /usr/local/bin/orc

# Linux (x64)
curl -L https://github.com/niradler/orc/releases/latest/download/orc-linux-x64 -o /usr/local/bin/orc && chmod +x /usr/local/bin/orc

# Linux (ARM64)
curl -L https://github.com/niradler/orc/releases/latest/download/orc-linux-arm64 -o /usr/local/bin/orc && chmod +x /usr/local/bin/orc

Windows: download orc-windows-x64.exe from the release page, rename it to orc.exe and put it on your PATH.

Each release also publishes checksums.txt.

Then start the daemon (foreground) or register it as a service:

bash
orc daemon start      # foreground
orc daemon install    # start now and at every login

See Configuration.

npm ​

Needs Bun >= 1.4.4 on PATH.

bash
npm install -g orc-ai
orc daemon start

TIP

orc daemon install refuses to register a service when orc lives under a per-shell Node path (nvm, fnm, volta, asdf, nodenv), because that path can disappear. Use a pre-built binary for a background service.

Docker ​

Published image: niradler/orc (latest and one tag per version, linux/amd64 and linux/arm64).

bash
docker run -d --name orc \
  -p 127.0.0.1:7700:7700 \
  -v orc-data:/data \
  -e ORC_API_SECRET=$(openssl rand -hex 32) \
  -e ANTHROPIC_API_KEY=$ANTHROPIC_API_KEY \
  niradler/orc:latest

orc-data holds the database, config, secret key, knowledge and logs. Add -v orc-home:/home/bun to keep agent CLI logins and the user flows, agents and packages under ~/.orc.

Or, from a clone of the repository, with the bundled docker-compose.yml:

bash
docker compose up -d
ItemValue
Port7700, bound to 0.0.0.0 inside the container
Database, config, secret, knowledge and logs/data/ (ORC_HOME, mounted as orc-data)
/home/bunOptional: agent CLI logins, session histories, and user flows/agents/packages under ~/.orc
Health checkGET /api/health every 30 s
Bundled agent CLIsNode, ACPX, Claude Code, Codex (versions pinned in the Dockerfile)
Default backendclaude (Anthropic SDK)

Set a secret before exposing the port

Without ORC_API_SECRET every endpoint is open, including job execution, which runs shell commands. Keep the port on 127.0.0.1 or set a strong secret.

Agent credentials are not included:

AgentProvide
claudeANTHROPIC_API_KEY
codex-cliOPENAI_API_KEY or a Codex login inside the container
ACPX agentsWhatever the launched agent requires

Mount your repositories into the container and use the container path as the project folder.

Compose environment ​

docker-compose.yml reads these from your shell or a .env file:

VariablePurpose
ANTHROPIC_API_KEYClaude backend
OPENAI_API_KEYCodex backend
ORC_API_SECRETAPI bearer secret
ORC_TELEGRAM_TOKENTelegram gateway
ORC_AGENT_LOOP_DEFAULT_BACKENDDefault backend (default claude)
AGENTAPI_URLagentapi server (default http://host.docker.internal:3284)
ORC_SSH_HOST~/.ssh/config host alias to run agents, terminals and git on

Compose mounts ~/.ssh read-only and copies it into the container with safe permissions.

Run agents on the host instead ​

Set ORC_AGENT_LOOP_DEFAULT_BACKEND=agentapi and run coder/agentapi on the host, wired back to ORC over MCP:

bash
agentapi server --allowed-hosts '*' -- \
  claude --allowedTools all \
         --mcp-config '{"mcpServers":{"orc":{"type":"http","url":"http://localhost:7700/mcp"}}}'

For running ORC on a shared server, see Self-hosting.

From source ​

bash
git clone https://github.com/niradler/orc
cd orc
bun install
bun run build

Run the CLI from the checkout:

bash
bun packages/cli/src/index.ts daemon start

Build standalone binaries into packages/cli/dist/:

bash
bun run --filter orc-ai build:bin

Build the desktop app (needs Bun >= 1.4.2 first on PATH):

bash
bun run --filter @orc/desktop dist        # installer for this machine -> packages/desktop/release
bun run --filter @orc/desktop dev         # run the app from source

Upgrading ​

To start using automatic desktop updates, manually install a build that contains the updater once. Earlier desktop builds cannot update themselves into this feature.

Database migrations run automatically when ORC opens the database. Back up ~/.orc/orc.db first if you want a rollback point.

MethodUpgrade
Desktop appInstalled macOS, Windows and Linux apps check for updates on their own. Settings → About shows the channel and Restart to update after the download. Installation waits for that action; quitting alone does not apply the update. You can still quit from the tray (Quit orc) and install the new installer over the old one. The app replaces ~/.orc/bin/orc on first launch.
BinaryRe-run the curl command, then restart the daemon (orc daemon stop, then start it again or let the service restart it).
npmnpm install -g orc-ai@latest, then restart the daemon.
Dockerdocker pull niradler/orc:latest and recreate the container, or docker compose pull && docker compose up -d.
Sourcegit pull, bun install, bun run build.

On macOS, ORC downloads the release disk image, verifies its SHA256, and checks the app identity, version, architecture and bundle integrity before stopping its daemon. Restart to update replaces the installed app and relaunches it, retaining the previous app in a hidden sibling update folder for recovery. The installation folder must be writable by your user; move the app out of the disk image into /Applications or ~/Applications first. This updater does not require an Apple developer account and does not change Gatekeeper settings. The normal first-open approval for an unnotarized app can still apply.

From the dashboard, Settings → Server → Restart ORC server restarts the running server without losing settings. It closes active terminals.

Check the running version:

bash
orc --version
curl -s http://127.0.0.1:7700/api/health
