Desktop app and web dashboard ​

A tour of every page in the ORC dashboard and what the desktop app adds on top of it.

The dashboard is served by the daemon at http://localhost:7700. The desktop app shows the same dashboard in its own window, so everything below applies to both.

Layout ​

Chat page ​

Chat in the sidebar, under Activity, opens the chat page at /chat. It is a regular page: the workspace header keeps your navigation and notifications, the sidebar keeps whatever width you chose, and Chat shows as the active page. The chat panel's full-screen button, and the full-screen button on Sessions (on the page or on a row) or in the Terminals session list, open the same page.

Below 1280px wide, the chat has no side panel: starting a chat from any page opens the chat page instead.

  • Session list: chats, coding agents running in ORC terminals, and live sessions discovered from your coding agents, each with its state. Click a chat to read it, a terminal agent to see its terminal, or a discovered session to resume it in chat. Collapse the list to a rail of icons with its state marks; expand it again from the rail.
  • Inspector: the panel button in the header shows the host, folder, branch, changed files, linked task and pull request for the selected session. When a terminal is running in that folder, a Diff tab shows its Git changes.
  • Terminal drawer: the terminal button in the header opens a shell in the session's folder below the conversation.
  • Drag a splitter, or focus it and use the arrow keys, to resize the list, inspector or drawer. Double-click to reset. The width is remembered.
  • The page keeps the workspace header and its single notification bell, and the sidebar at the width you chose. Close chat returns to the page you came from.
  • The URL keeps the selected session and which panels are open, so reload and Back restore them.
  • The header shows the recorded project and session title. Unlinked terminal agents show Unknown until agent activity supplies a state; they appear only in All projects while project ownership is unavailable. The Activity session list uses the same compact row design, retaining search, filters, task links and resume actions.

On a phone the list opens full screen from Sessions in the chat header and the inspector opens as a sheet. The three-dot Session actions menu shows labeled actions with touch-sized rows on phones. It closes when you tap elsewhere in the chat or press Escape. Choosing an action also closes the menu; opening Session settings keeps the conversation and your draft in place. Agent, workspace and branch pickers also close when you tap outside them. Opening the list sets sessionList=show in the URL, so reload and Back restore it. Closing the page also returns to the original page after navigating Back and Forward.

The Activity page: task metrics plus recent jobs, memories and sessions for the selected project.

The task board. Switch between Board (kanban) and Table views and filter the list. The GitHub panel lists issues and pull requests from known repositories (yours, assigned to you, or all open) and links them to tasks.

Sessions ​

Live and archived sessions from Claude Code, Codex, Cursor, Gemini CLI and OpenCode on this machine or the selected host. Working sessions update live; waiting sessions stay available to resume in a terminal or in chat. Search across archived conversations. See Live sessions.

Filter the list by state with All, Needs you, Working and Done. Each filter shows its count, and failed sessions count as Needs you. A session that finished after you last opened it shows Done until you open it. This browser remembers what you have seen. The chat session history has the same filters.

While your pointer is over the list, or a row has keyboard focus, rows stay where they are. States still update in place. When the order would change, an N updated button appears. Click it, or move away from the list, to apply the new order.

Terminals ​

Desktop browser, files and editor ​

In the Electron desktop app, File → Browser and files (Ctrl/Cmd+Shift+B), or Browser and files in the tray menu, opens a panel beside your conversation. Chat links and file attachments open in this panel. Enter an HTTP/HTTPS address and use Back, Forward and Reload. The external-link icon opens the page in your system browser; Ctrl/Cmd-clicking a web link does the same.

Each conversation keeps its own browser and file tabs. The panel stays docked beside the conversation and opens only when you ask for it or follow a link; drag the divider (or use arrow keys on it) to resize. The Files tab browses every file in the session's folder and opens a file in an editor tab. Closing the panel keeps tabs and drafts in memory; closing a modified file asks before discarding it. Reloading or quitting discards these previews after the unsaved-change warning.

The folder icon (Open file) uses the native picker for local files. Chat and MCP file paths resolve inside the selected session's folder on its execution host; paths outside that folder and symlinks escaping it are denied. Remote file previews require Python 3 on the SSH host. Files must be UTF-8 text up to 1 MiB. Markdown has Read, Edit and Split modes; code uses the existing editor. Text up to 200 KB can be saved explicitly. A save fails if the file changed on disk, keeping your draft until you reload or resolve the change. HTML stays source code. The external-link icon opens the source in VS Code, including known SSH hosts; it is disabled when the desktop cannot identify a remote API host's filesystem.

PNG, JPEG, GIF, WebP, BMP and ICO images can also be previewed, up to 8 MiB and 16 megapixels for native-picker images. Images are read-only; native-picker images use native decoding and display a static image. Workspace images use the browser's image decoder. PDF and Office previews are not included.

The browser uses a separate session without ORC's API credentials, cookies or desktop bridge. Camera, microphone, location and other site permissions are blocked. Browser downloads are staged privately (16 MB each, four across the app); Browser profile, display & recording lists their status and saves completed files to the selected chat workspace. Interrupted/failed downloads are never reported as saved. Each chat starts with a temporary cookie/storage profile. Settings → Browser → Saved browser profiles creates named profiles; select one under Browser profile, display & recording in the browser panel to remember site logins. Selecting the same profile in another chat explicitly shares that profile's site storage. Temporary chats stay isolated. Profile choices and saved cookies survive app restart; session-only cookies follow the site's expiry rules. Switching profiles closes that chat's browser tabs after confirmation and preserves file drafts. Use + to open a browser tab and each tab's close button to close it. Popups open another isolated tab. Limits are eight tabs per chat and 24 total; reaching a limit asks you to close a tab, without eviction. Tab IDs, URLs and the selected tab restore when you return after app restart. Temporary mode does not persist cookies; saved tab URLs are still restored. Browser settings also offers profile rename and removal. Removal asks for native confirmation, closes its tabs, clears cookies/site data/cache and resets chat selections.

Import selected browser logins, under Browser settings, connects to a local Chrome/Edge debugging endpoint you explicitly enable. Choose the destination ORC profile, enter the loopback debugging port, approve any source-browser prompt, then select sites from its open pages. Only those sites' applicable cookies are copied; their values and the source connection never reach agents or the API. The connection closes after import or cancellation. Live transfer copies cookies applicable to the selected site's root and currently open page path; passwords, localStorage, IndexedDB and device-bound sessions are not transferred. Partitioned cookies are skipped and counts are reported. Verify the login; some sites require signing in again. Modern Windows Chrome/Edge app-bound cookie files cannot be decrypted by ORC. Chrome's newer native consent flow and Mac/Linux interaction have not been validated here; the verified source was an isolated Windows Edge profile with a loopback debugging port. Existing personal profiles may not expose one.

Scan browser profiles provides direct cookie-store import from Firefox/Zen, Safari on macOS, and supported Chromium-family stores on macOS/Linux. Legacy Windows Helium DPAPI stores are supported; app-bound Windows stores require the live connection. Select a source profile and individual sites. Reads use readonly SQLite snapshots; keys are obtained only after selection through OS facilities. macOS may request Keychain/Full Disk Access approval; Linux encrypted stores need secret-tool and an unlocked Secret Service. Missing keys and skipped cookies are reported, never treated as a guaranteed login. Containers and partitioned cookies are excluded. Direct Firefox import was exercised with isolated Windows demo data; other OS integrations still require their native platform acceptance checks.

Expand Browser display & recording to change appearance/viewport, record the guest page, save WebM to the chat workspace, and play/download it. UI recording lasts up to 60 seconds; agent requests can choose up to 180 seconds. Recordings are limited to 16 MB and contain only the browser guest, without audio or ORC UI. If workspace saving fails, the completed file remains downloadable in that window.

Agents can use preview MCP tools to show a file or URL in the selected conversation. Allow agent browser control, on by default, is controlled in the chat's Session settings before you open a preview. It permits snapshots, screenshots, clicking, typing, key presses, scrolling, hovering, selecting, dragging, condition waits, guest JavaScript evaluation, cross-origin frame targeting, semantic locators, dialogs, recording, appearance, viewport changes and explicit workspace-file uploads/download retrieval. This includes pages you sign into there. Turning the switch off revokes control. These tools cannot inspect the ORC app or its bridge or edit preview files. Upload paths must remain inside the chat's trusted workspace. The guest has a minimal standard prompt() adapter because Electron disables that browser function; it exposes no application API, credentials, filesystem access or general IPC. Browser content is untrusted page data, never agent instructions. If a mutating browser command is still pending when control is revoked or its guest is hidden/switched, ORC closes that guest to prevent delayed execution. The tab shows an interruption message; Reload restores its URL and profile. File drafts are preserved. An evaluation timeout can require the same recovery.

Settings → Browser controls agent browser access for the whole desktop and whether chat web links open in ORC or your system browser. Settings are stored in browser-preferences.json in Electron's user-data folder and survive restarts. Per-chat permissions use browser-chat-permissions.json; named profile metadata and explicit chat selections use browser-profiles.json. These metadata files do not contain cookies or passwords; Chromium owns the separate profile partitions. Turning global agent access off overrides every chat's switch immediately. With global access on, the chat's Session settings switch can still disable control for that conversation. The browser toolbar does not contain a second access switch. Files and explicit MCP preview requests continue to open in the panel.

This flow is desktop-only; the web and phone UI are unchanged.

Browser terminals for shells and coding agents, with split panes and Files and Git panels beside them. Terminals run on the selected execution host. See Terminal workspace.

Projects ​

Create, edit and archive projects. A project has a name, description, tags and an optional Git remote URL. Deleting a project deletes its memories and scratchpads and keeps its tasks, jobs and sessions without a project.

Memories ​

Short project facts (ports, conventions, decisions) that agents load at session start. Create, edit, and view each memory's change history. Under Knowledge → Memories.

Knowledge ​

Knowledge bases: upload PDFs, Office files, HTML, CSV and Markdown, write Markdown in place, or register a folder to copy in. Search returns cited passages. Each knowledge base can have a digest agent that maintains it on a schedule.

Jobs ​

Scheduled and on-demand automation. A job runs a shell command, an agent or creates a task, triggered manually, by cron, by a file watch, once, or by a webhook. Each job keeps its run history with logs and linked agent sessions.

The job editor uses Trigger, Destination and Settings tabs. Choose Manual, Webhook or Schedule; schedules offer time/day controls and Advanced cron, with an explicit timezone. Existing watch, one-shot and bridge-message jobs keep their trigger. New jobs stay disabled until you enable them; a disabled job can still run manually.

Destination selects the project, working directory and execution host (local or a configured SSH host). Commands offer sh, bash, zsh, fish, PowerShell and cmd presets, plus a custom executable and one argument per line. The script is appended as the final argument, so a custom interpreter needs its command option, such as -c. The interpreter must be installed on the destination. Host default uses sh on Unix and Windows PowerShell on Windows; jobs saved before this setting retain sh.

Agent jobs save a prompt, backend, optional model, explicit automatic tool approval and supported launch options. Agent and model use the same picker as Chat: enabled agents, models reported by the provider on the job's selected host/directory, Agent default and an explicit Custom model option. A saved model remains selectable if discovery is temporarily unavailable. Changing agents clears the previous model and launch options. New agent jobs default to an isolated, detached Git worktree for each run. HEAD inherits the project checkout's current commit; override it with a branch or remote-tracking ref. ORC does not fetch, reset or push the base. Clean up worktree after a successful run is off by default. When enabled, cleanup removes only a successful, clean worktree with no commits absent from its starting base; failed runs, untracked/ignored files and new commits are retained. Run history records the path and cleanup result. HTTP-only agent backends cannot use these local host, worktree or environment settings.

Environment variables live under Settings. Mark a value Secret to mask its input, encrypt it at rest and omit its value from read responses. After saving, leave a saved secret blank to keep it; enter a replacement to rotate it. Exact secret values are redacted from job output and saved agent summaries, including across output chunks. This does not scrub transformed values or files and logs written by the script itself. Values are single-line; ORC_ names are reserved. Back up ~/.orc/secret.key with the database: saved secrets cannot be decrypted without that machine key.

To see a result, open the job and select View result under Recent runs. This shows the saved output and errors. Session summary opens the audit record. For an agent run with a native session ID, Open agent session opens the actual conversation in Sessions, where the existing transcript/resume controls apply. ORC discovers that conversation on the run's own host without changing the globally selected host. If the provider has not retained a conversation yet, the saved result remains available and the interface explains that the native conversation is missing.

Webhooks ​

Inbound event sources. Configure a webhook once, then connect it to one or more jobs, each with its own event filters and action.

Notifications ​

When a session you are not viewing needs your approval, has a question or fails, ORC shows a Needs you notification and plays a short chime. Notifications settle for about one second before appearing and repeated snapshots do not repeat the alert. The header bell opens a menu containing generic notifications, including human requests, agent outcomes and job results. Open a request to answer or review its action. Read and dismissed state is shared across clients.

Desktop browsers show toasts. Needs-you toasts stay until dismissed or resolved; Done toasts are silent and close after six seconds, pausing on hover or focus. Sessions finishing together collapse into one notification. Use Alt+N or Open notifications in the command palette to reach notifications.

On all screens, the bell in the workspace header shows an unread count, including while the chat is open. New notifications never open the panel automatically. Tap the bell to read or dismiss them. History remains until dismissed or expired (30 days by default). Configure notification and audit retention in Settings → Storage. See Notifications and Human requests.

Settings → Notifications → Sound controls the browser chime, volume and per-project sound mute. Preferences are saved in this browser. Audio starts after your first interaction. Browser/PWA push remains separately opt-in and requires HTTPS (and Home Screen installation on iOS); it delivers background approvals, questions, chat replies and job results while ORC is unfocused. Job pushes follow the job's notify setting and start with new runs. See Installation.

The Electron desktop app also sends native notifications while its window is unfocused, minimized or hidden. Clicking one brings ORC forward, opens its destination and marks that notification read, clearing it from the inbox. A grouped done toast opens its destination only; clear the collapsed items from the notification menu. Done notifications are silent; native Needs-you sound follows the OS.

Browser app and updates ​

The dashboard installs as a browser app and serves an offline shell when the network is unreachable. An open tab or installed app runs the build it was loaded with, and the server replaces that build when it is updated. Reaching a page whose code is gone then reloads the app once, without asking, so unsaved input in the current page is lost; the reload loads the current build. If it does not fix the problem, ORC shows the failing error with Reload and Copy details instead of a generic error page, so a report carries the real message and stack.

Audit ​

Lifecycle and knowledge events with filters and expandable details. Recorded session summaries remain in collapsed history. Audit retention defaults to 90 days and is configurable in Settings → Storage. Use Sessions to read full conversations or resume an agent.

Skills ​

Reusable agent instructions stored as skill folders. Import skills from a repository or from local agent folders, create your own, edit files, view history, and assign skills to projects. See Skills.

Packages ​

Packages bundle instructions, skills and tools for reuse. Launch a package in chat or a terminal on the host and folder you choose. See Agent packages.

Agents ​

Shared specialist agent definitions: instructions, model and tools, reusable across coding agents and packable into packages. Under Library → Agents.

Rules ​

Applied rules and their outcomes per workspace, plus rule settings for enforcement and agent assignment. See Agent rules.

Scratchpads ​

Working documents, diagrams and HTML pages that you or an agent create and come back to. Agents use the pad_* MCP tools. Share one by copying its link.

HTML pads receive the ORC HTML kit in both the editor preview and chat artifacts: dashboard theme tokens, base styles, cards, tables, stats, badges, tabs and chart wrappers. Use orc-* classes to build a native-looking page without a custom <style> block. The kit is inlined at render time, needs no network request, and does not change the saved HTML. Custom CSS and JavaScript still work.

Pin the kit stylesheet in your HTML head to keep its version as the kit evolves:

html
<meta name="orc-kit" content="1">

Bundled older versions remain available. A missing or unknown version uses the current kit. Both previews follow the dashboard's light/dark theme; changing the theme rebuilds the iframe document, resetting its running scripts and local UI state. The saved pad content stays the same.

Kit tabs support clicking, Left/Right arrows with wrapping, and Home/End. Only the selected panel is shown. The kit does not grant ORC API access: editor pads still require Render with ORC access, and chat artifacts retain their opaque sandbox and network-blocking policy. Prefer inline SVG for charts that must work in both views; a CDN chart library is blocked in chat.

For concise component markup, use built-in custom elements such as <orc-card>, <orc-stat label="Open tasks" value="12">, <orc-badge tone="success">, <orc-table> and <orc-chart>. <orc-tabs> generates accessible tab controls from labeled <orc-tab> panels. These components reuse the kit with no additional dependencies or network requests; ordinary HTML with orc-* classes remains supported.

Agents can load the component list, copy-paste skeleton and chart guidance with skill_read for orc-platform, ref references/html-kit.md. See Skills.

Enabled agents, including custom ACPX ids, appear in the chat agent picker:

Chat turn progress ​

Finished turns fold tool calls and intermediate narration into one expandable line; your message and the final reply remain visible. Expand it to inspect file diffs, commands and output, reads, and searches. Failed tools stay marked.

During a response, a quiet status line shows elapsed time and the current tool. Scrolling up pauses automatic following; Jump to latest returns to the bottom. Stop remains beside Send. Working indicators are static.

Each turn keeps its duration and completed, stopped, or failed outcome across reloads. Duration uses the agent's reported value when available, otherwise server elapsed time, including waits for input. Older turns without timing show counts only. Stopped turns retain partial work; unfinished tool calls read Incomplete. Individual tool durations are not shown.

A turn that goes quiet does not run forever: after 15 minutes without any agent activity ORC stops it, and the conversation and a notification say it was stopped for inactivity. A turn waiting for your answer or approval, or with a command still running, is not idle and is not stopped; a 4-hour absolute limit still applies so a stuck agent cannot hold a chat worker indefinitely.

Composer controls ​

The composer groups folder, branch, agent/model and permissions into compact controls. Phones and narrow desktop panels use icons; wide composers show labels. Send queues the next message while a reply is running. If this session is already responding, or every chat worker is busy, that message stays queued and sends when the turn ends, without an error. Open the pending list to edit a message, move it up or down, remove it, or send it ahead of the current reply. An expanded pending list stays open across busy-worker retries. After it drains, the next list starts collapsed. If a first send loses its connection, chat looks for the original message and reconnects to its thread. Recovery stops after 15 seconds, or 60 seconds when the server may still be preparing the turn. If recovery cannot find it, the message returns to a paused queue with its attachments. Retrying keeps the message's ID so the server can recover the original turn without starting another one. Every icon has an accessible name and opens its picker with the full details; phone touch targets are at least 44px. Send stays visible at the right.

The folder picker shows the full path, copy action, recent folders, host choices when configured, and browsing. Branch/worktree controls appear for Git folders. Folder and branch controls hide after launch; conversation details show the working folder. Changing agent after launch starts a separate session. The model picker disables changes during a response or when the backend selects its own model. Effort stays in agent options. The permissions control appears for a non-default mode only when the backend supports changing it live.

Pasting at least 16 KiB or 200 lines attaches the text as pasted-text-N.txt. Use Ctrl/Cmd+Shift+V to paste inline instead. Typing @ does not attach files.

Quitting the app (Quit orc) stops the daemon only if the app started it.

If another application occupies the configured port, desktop automatically starts ORC on an available port bound to 127.0.0.1. It saves the successful endpoint in ~/.orc/config.json, so the CLI and stdio MCP use the same port by default. Explicit CLI flags, environment variables and project configuration keep their normal precedence; update pinned ports or URLs in external integrations yourself.

Desktop checks the daemon's runtime identity, compatible version (same major and minor), database, configuration and authentication before attaching. It never starts another daemon while the daemon PID is alive, even if that daemon is unhealthy or uses different data. Authentication and configuration errors offer Retry or Quit, with the reason shown. It does not stop an existing daemon or the application occupying the preferred port.

Upgrading an already-running older daemon: releases without daemon.json cannot provide this identity check. Stop that daemon once and start it with the updated ORC, then choose Retry in desktop. Desktop does not attach to an unverified daemon or send it the configured secret.

FlagEffect
--hiddenStart without opening a window

Links to other sites open in the desktop preview panel. Use its external-link icon or Ctrl/Cmd-click a web link to open your system browser.

Install a desktop build containing this updater manually once. Older builds do not have an updater and cannot automatically install the feature itself; subsequent macOS, Windows and Linux updates can use the flow below.

An installed macOS, Windows or Linux app checks GitHub Releases for updates when it starts and every four hours. The download runs in the background. Settings → About shows the current version, the update channel, Check now, and the last result. Restart to update installs the download; quitting alone does not apply it. The app stops the daemon it started, then the new version starts that daemon again. Tasks and sessions stay in ~/.orc. A daemon the app did not start is left running.

Stable uses the latest GitHub release. Preview also accepts a newer prerelease. Uncheck Check for updates to stop automatic checks; Check now still works. These choices are stored in the desktop app's own settings, not in ~/.orc/config.json. Source runs and electron . do not download updates.

Wait for an active check or download to finish before changing channels. Changing channels discards the previous channel's ready update. Failed settings saves retain the prior preferences and show an error; failed update actions can be retried.

Windows installs the NSIS package. Linux replaces the AppImage. macOS verifies the release disk image and its app bundle, then replaces the app through a separate installer helper and keeps the previous app for recovery. The Mac installation folder must be writable; updates work without a paid Apple developer account. macOS first-open approval for an unnotarized app can still apply. Manual upgrade steps remain in Upgrading.
